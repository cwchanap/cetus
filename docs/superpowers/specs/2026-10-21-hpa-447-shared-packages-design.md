# HPA-447 — Cross-platform Shared Packages Design

**Linear:** [HPA-447](https://linear.app/cwchanap/issue/HPA-447/extract-the-cetusgames-cetusshared-and-cetusapi-client-packages)  
**Baseline:** `main` at `16fa956826a1f1cd6b1e0f14f62df9ddc9f9a9a3` (2026-10-21, America/Vancouver); HPA-444 and HPA-446 are Done.  
**Delivery:** One PR for **one Linear ticket**, with reviewable sequential implementation commits. This supersedes the ticket text's "one PR per package"; three independent PRs would split a single task and complicate dependency ordering. This draft initially changes docs only.

## Goal

Make the existing Astro web app consume three portable workspace packages so an eventual Expo host can reuse **game rules**, **domain contracts**, and **API requests** without importing Astro, Pixi renderers, browser globals, web server services, or Turso. **Preserve the behavior of all 23 web games, authentication, scoring, achievements and leaderboards.** This is an extraction, not the React or mobile implementation.

## Verified code inventory

- Bun 1.3.14 workspaces already cover `apps/*` and `packages/*`; `apps/web`, `packages/config`, and `packages/tokens` exist. Root scripts still forward most checks to `apps/web`; Turbo has tasks for `build`, `test`, and `typecheck`.
- `apps/web/src/lib/games/core/ScoreManager.ts` and `core/types.ts` import **web** `scoreService` and `server/validations` types. `BaseGame.ts` imports `GameID` from web `games.ts`. These are real package-boundary leaks after HPA-444.
- `scoreService.ts` contains both browser `fetch('/api/scores')` and presentation-oriented helpers, while `ScoreManager` defaults to that browser transport. The injection seam from HPA-444 exists, but production callers commonly rely on its default.
- `apps/web/src/lib/achievements.ts` uses a DB-derived `UserAchievementRecord` type; `games/shared/types.ts` aliases types from several game-local modules. Moving those files naively would create `shared -> games -> shared` dependencies.
- `apps/web/src/lib/server/validations.ts` mixes Zod schemas/types (portable) with `validateBody(Request)` and `validateQuery(URL)` helpers (HTTP host adapters). `preferences.ts` mixes portable types/defaults with `window`, storage and DOM event utilities. `utils.ts` mixes `cn` (Tailwind-specific) with pure date/contribution-grid helpers.
- There are **12 application API paths and 14 methods**: scores POST, scores/best GET, scores/history GET, leaderboard GET, challenges GET, challenges/xp GET, login-rewards GET, login-rewards/claim POST, settings GET/POST, user/profile POST, user/avatar POST/DELETE, user/update-streaks POST. The original ticket's "13 routes" is not the current file-level inventory. `api/auth/[...all]` is Better Auth's owned interface and `api/dev/add-test-scores` is development-only. Neither belongs in the application client. The current profile route has **POST only**; profile reads use the existing auth/session view, not a new GET endpoint.
- The web has 20 BaseGame-based games plus 3 intentionally handle-based games (Circuit Hacker, Satellite Sync, Ice Slide). Their existing game/initializer patterns are preserved. `GameInitializer` has no production importers and stays web-side rather than undergoing a speculative rewrite.

## Package dependency direction

```text
apps/web (Astro routes, UI, web adapters, renderers, auth, DB)
  ├─> @cetus/api-client ──> @cetus/shared
  ├─> @cetus/games ───────> @cetus/shared
  └─> @cetus/shared

@cetus/shared -> zod (and small dependency-free domain utilities)
@cetus/games -> @cetus/shared
@cetus/api-client -> @cetus/shared
```

No inverse import edges; no package imports from `apps/web`, `@/lib`, Astro, Better Auth, DOM/Pixi, or a server database module. Reuse existing `@cetus/config`, root ESLint/Prettier, workspaces, lockfile, and Turbo; no bundler, publishing pipeline, code generation, runtime plugin registry, or new framework.

### `@cetus/shared`: identity, domain and wire contracts

- Move `games.ts` (`GameID`, `GAMES`, metadata), `organisms.ts`, `challenges.ts`, `loginRewards.ts`, and the **pure** portions of `achievements.ts`, `preferences.ts`, and `utils.ts`, with their tests.
- Define portable game-result/achievement-check DTOs on the shared side of the package boundary. Detach any `UserAchievementRecord` database dependency (keep the DB-specific enrichment type/adapter in web), and avoid the `games/shared/types.ts` aliases pointing back to `@cetus/games`. Keep a single canonical DTO definition where possible; move game-local, runtime-only types with the game. Preserve the current achievement condition functions and results.
- Move the Zod schemas (`scoreSubmissionSchema`, `scoreContextSchema`, `scorePlatformSchema`, `leaderboardQuerySchema`, `profileUpdateSchema`, `paginationQuerySchema`) into `@cetus/shared`. Move *only* the schemas and portable types, not HTTP/body parsing helpers; retain `validateBody` and `validateQuery` in `apps/web/src/lib/server` importing shared schemas.
- Define **plain TypeScript request/response DTOs** for all 14 application API operations from existing response JSON shapes (nullable scores, leaderboards, profile/settings/avatar and reward payloads). Reuse the existing Zod **request** schemas for server validation, but do **not** add runtime Zod validation for first-party response bodies or error envelopes. Make the types a **server-checked contract**: in each of the 12 app route files, type successful response literals with `jsonResponse<SpecificResponseDto>(...)` (or `satisfies SpecificResponseDto` when generics are inconvenient); type `codedErrorResponse` against the shared `{ error: string; code: ... }` envelope, preserving current HTTP codes. The existing `jsonResponse<T>` and `codedErrorResponse<C>` helpers in `apps/web/src/lib/server/api-utils.ts` provide the seam. Retain the existing narrow of `unknown` response bodies for `SCORE_CONTEXT_UNAVAILABLE` in the API client without a new parser. Route/client tests must cover the wire contracts; preserve JSON date strings. No new routes or DB DTO mirroring.
- Keep client preference storage, `matchMedia`, browser event dispatch, `cn`, styling and user/avatar UI inside web.

### `@cetus/games`: game simulation only

- Move the portable core (`BaseGame`, `GameTimer`, `ScoreManager`, emitter, errors as applicable, run guard and core contracts), shared geometry/grid/randomness helpers, and all 23 games' **game state, rules, generators and pure data** with adjacent tests.
- Keep `init*.ts`, `*Renderer.ts`, `renderer.ts`, `BaseRenderer`, `RendererFactory`, `GameInitializer`, `renderers/**`, any DOM controllers (e.g. Ice Slide daily-leaderboard view) and audio/browser integrations inside `apps/web`. Resolve cross-file imports explicitly: renderers import logic from `@cetus/games`, not the reverse. Preserve the two styles of game lifecycle (BaseGame and handle-based).
- Replace all game-core web imports with `@cetus/shared` portable types. In particular, **do not import** `apps/web`'s `scoreService` from `ScoreManager`; move the HPA-444 `ScoreSubmitter` contract to shared. Use **one compile-time enforcement mechanism**: `BaseGameConfig.submitScore: ScoreSubmitter` is required, and each concrete BaseGame constructor takes `config: Partial<SpecificConfig> & Pick<BaseGameConfig, 'submitScore'>` with no empty default. Pure static `DEFAULT_*_CONFIG` objects are typed `Omit<SpecificConfig, 'submitScore'>` and merged with the host-provided submitter. Remove `ScoreManagerConfig.submitScore`; `ScoreManager` becomes transport-free for ordinary scoring (including Satellite Sync). Change the sole score-save call to `scoreManager.saveFinalScore(submitScore, gameData?, score?)` with the **required callback as first argument** (TypeScript cannot put a required parameter after optional/default parameters). `BaseGame.end()` passes its required `this.config.submitScore`; preserve callable method `this` semantics if the host supplies a method rather than a standalone function. One negative TypeScript fixture on `BaseGameConfig` suffices; the compiler errors at concrete constructors and web call sites provide the migration checklist. Delete obsolete `TRANSPORT_UNAVAILABLE` producer/code/tests when retiring the browser fallback, after confirming no live consumers; keep the meaningful public 401, context-unavailable and network error behaviors. Preserve local completion and stale-run semantics.
- **Defer `createGameLoop(game, tick)`** despite its mention in the original ticket. This PR would have zero real callers; existing browser game loops already drive `update(delta)`. Define the frame-loop API alongside its first genuine consumer (likely the Skia game-canvas work in HPA-533, or whichever earlier mobile/game-screen ticket owns the host loop) so its signature is based on actual host requirements. No unconsumed helper or syntactic test is added here.
- Configure **both `packages/games` and `packages/shared`** with ES libraries and **no DOM lib**, plus isolated typecheck scripts. The hoisted Bun linker allows undeclared dependencies, and `skipLibCheck` does not reliably catch Pixi leaks; add a persistent root ESLint `no-restricted-imports` rule scoped to `packages/**` for `pixi.js`, Astro, Better Auth, Kysely/LibSQL, `@/` aliases and paths into `apps/web`. Move `isEditableTarget` (currently in `games/shared/utils.ts` and dependent on `HTMLElement`) to the web host, updating its many game-keyboard callers. For fast mechanical import rewriting across game folders, export public game source subpaths via `"exports": { ".": "./src/index.ts", "./*": "./src/*.ts" }` where the actual workspace layout permits; avoid a manually maintained list of ~150 files. Keep package-level dependency direction explicit and cycle-free.

### `@cetus/api-client`: one typed transport for the app routes

- A simple `createApiClient({ baseUrl?, fetchImpl?, getHeaders? })` factory with typed per-route operations. Default `baseUrl` behaves as a relative URL for web; a native caller supplies an absolute host. Inject `fetchImpl` for tests and `getHeaders` for the future mobile session cookie; do not implement a second authentication system.
- Reuse shared request DTOs and plain TypeScript **response types** for successful first-party calls; do not create 14 Zod response parsers. Reuse the existing `unknown` body/property guard for `SCORE_CONTEXT_UNAVAILABLE` rather than adding a Zod parser; handle non-2xx, 401, 400, 503, malformed JSON and network failure without losing meaningful public score error codes. Drop `TRANSPORT_UNAVAILABLE` when the obsolete implicit browser transport is removed and TypeScript now mandates an injected submitter. Retain the live web-facing `getUserBestScore(): number | null` fallback at the **web adapter** boundary, not inside the strict API client. Delete the unused browser history helper rather than creating a new `[]` fallback adapter.
- For avatar POST use `FormData` without manually setting multipart `Content-Type`; avatar DELETE stays supported. Do not parse Better Auth endpoints as application routes.
- Migrate direct `/api/*` fetch call sites in web browser scripts and `scoreService` through the client, preserving toast ordering, stale-run suppression and display behavior. Keep the live `getUserBestScore` `null` fallback as a thin adapter; **delete dead browser `getUserGameHistory`** instead of creating a new `[]` fallback adapter, after confirming zero live callers (the username profile page imports the server query of that name). Do not invent web adapters for currently unused client operations. The server's internal calls and Better Auth transport are not part of this "no handwritten fetch" goal.

## Validation and out of scope

**Invariant checks:** the package graph has no cycle or reverse dependency; isolated no-DOM typechecks pass for both `games` and `shared` and persistent ESLint rules forbid forbidden imports. A single negative `BaseGameConfig` TypeScript fixture rejects missing `submitScore`, while concrete constructors propagate the required config. `ScoreManager` is valid for scoring-only use. Server routes' successful `jsonResponse<ResponseDto>` literals and coded-error helper are tied to shared DTOs. Root Vitest `test.projects` runs web and package tests under `bun run test:run`/`test:coverage`; one consolidated `coverage/` upload includes extracted game logic. Web remains renderer/auth owner, 23 IDs stay stable, and all 12 paths / 14 operations have typed client tests.

**Behavior checks:** the same score payload and meaningful error code reaches the same API route from web; injected submitter works with BaseGame and handle-based games; local end/replay remains unblocked by pending POST; stale achievements stay suppressed; contextual Ice Slide leaderboard and all existing game tests stay green. Each stage exits with typecheck **and production build**; Stage 2 additionally exercises an authenticated Playwright score-submit smoke for one BaseGame game and one handle-based game against an isolated test DB. Full Playwright covers navigation, scoring, preferences and auth later.

**Excluded:** Expo and native UI/Skia, React conversion, the unconsumed `createGameLoop` helper, new endpoints (especially nonexistent `GET /api/user/profile`), DB migrations, changes to Better Auth, new game mechanics, artwork/audio assets, arbitrary state-machine frameworks and backward-compatibility shims.

## Decisions and risks for implementation review

1. **Portable DTO type cycles:** resolve at the source, not with TS path aliases that hide a cycle. Confirm the type-only dependencies in `achievements.ts` and `games/shared/types.ts` before moving files.
2. **Score injection coverage:** use the **required BaseGame config field + required `saveFinalScore` submitter argument** only, not overlapping optional alternatives, manual 20-constructor audit or multiple negative fixtures. The compiler is the coverage gate; propagate constructor errors into initializers, web pages and tests. Keep Satellite Sync's scoring-only `ScoreManager` transport-free, and preserve all three handle-based games' explicit save path.
3. **API mismatch:** code inventory beats the ticket's "13 routes". Cover the existing 14 methods. Do not add a profile GET just to match wording.
4. **No DOM types:** if a supposedly portable game file mentions a browser/Pixi type, leave the browser-facing adapter in web and expose a plain type at the boundary rather than widening the entire game's tsconfig to include DOM.
5. **No behavior refactor:** retain scores, challenges, achievement results, date serialization and **live** caller-facing fallbacks. Typed route response literals and existing route tests enforce shared DTOs instead of runtime response parsers. Remove only demonstrably dead helpers and obsolete transport-unavailable plumbing. Save incidental cleanups for a future ticket.
6. **CI/coverage boundary:** standard root test/coverage commands must include moved suites at Stage 1, not Stage 4; retain coverage thresholds and upload a consolidated report.
7. **Developer guide drift:** the canonical `CLAUDE.md` (also presented as `AGENTS.md`) incorrectly claims `GET` and `PUT /api/user/profile`. The actual route exports `POST` only; correct both stale entries in Stage 4's documentation update.
