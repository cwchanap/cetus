# HPA-393 — app-core hooks and 23 React GameScreens: design

Status: **proposed / planning only** (2026-10-27)  
Linear: https://linear.app/cwchanap/issue/HPA-393/build-cetusapp-core-and-move-all-23-web-game-pages-onto-gamescreen  
Base: current `main` after merged HPA-447 (#95) and HPA-379 (#97). One implementation PR for this single Linear issue.

## Goal

Turn all 23 game pages into thin Astro routes that mount **per-route React islands**, reusing `GameScreen` as a small shared component where appropriate. Keep game rules and persistence in existing `@cetus/games` / `@cetus/api-client` layers. Extract **only the portable session hook needed by Snake and the migrated standard games** into `@cetus/app-core`; defer speculative data hooks and field-plate React rewrites. Expo can reuse the proven session lifecycle later. Preserve existing URLs, features, game feel, responsive styling, accessible interactions, submission/reward semantics and each existing `window.<game>Game` debug handle.

## Verified starting point

- Bun workspace and `@cetus/{shared,games,api-client,ui,tokens,config}` exist. Astro 5 with `@astrojs/react` and React 19 is already integrated. Do not repeat HPA-379 or HPA-447.
- `apps/web/src/components/games/GamePage.astro` remains by design, with six named slots and SSR-only React GameTitle/GameStats/GameControls/GameOverlay. Its game scripts live at page root because Astro drops scripts nested in named slots. HPA-393 owns removing this compatibility shell.
- `apps/web/src/pages/snake/index.astro` has an imperative root `DOMContentLoaded` script calling `initSnakeGameFramework()`, and `apps/web/src/lib/games/snake/initFramework.ts` uses `document.getElementById('snake-container')`, imperatively updates HUD/overlay/buttons, owns keyboard/unload handlers and a single rAF loop. `SnakeGame` itself is portable in `packages/games`.
- `BaseGame` already injects its mandatory `submitScore` callback and saves in `end()`, emitting a structured end result **after** save completion. Its `onEnd` callback is called **before** awaiting save. A `'end'` event is also forwarded from the timer without a structured payload. Never treat all `end` events as a saved result or submit the score a second time.
- `apps/web/src/lib/services/scoreService.ts` is an existing web adapter over `createApiClient()`, and the shared `AppNotifications` island installs `window.showAchievementAward` and `window.showChallengeComplete`. Preserve the web-only notification boundary and stale-run suppression.
- **Nineteen** pages use `GamePage.astro`: Snake + fifteen standard games + three handle-based games (Circuit Hacker, Satellite Sync, Ice Slide). The latter have web-side `start/stop/cleanup/getGame` handles and existing score saving. The remaining four pages (Tetris, 2048, Bejeweled, Bubble Shooter) have bespoke field-plate layout and ~5,500 lines of existing imperative controllers; they never use `GamePage.astro` and must preserve their distinct UX. **Deleting the old shell depends on migrating the 19 users, not on finishing field plates.**
- `@cetus/api-client` exposes typed `getLeaderboard`, `getChallenges`, `getChallengeXp`, `getLoginRewardStatus`, `claimLoginReward`, `getBestScore`, `getScoreHistory`, `updateProfile`, `uploadAvatar`, `deleteAvatar` and `submitScore`. It has **no GET profile or GET achievements** method. Profile/achievement read state starts from server-provided serializable data or existing user/session state; do not invent endpoints.
- Root Vitest aggregates web, UI, shared, games and API-client projects; root coverage collects `packages/*/src/**` with a >=90% gate. Existing `apps/web/e2e/games/play-coverage.spec.ts` plus per-game Playwright specs exercise the existing fixed ID and debug-handle contracts. There is no `ClientRouter`, View Transitions or `transition:persist` in the web app: cross-route navigation is a full-page reload. Root ESLint enforces package direction; extend it rather than adding another checker.
- `packages/ui/src/components/{game-overlay,game-controls,game-stats}.tsx` currently renders **imperative defaults** (`hidden` overlay with `0` score, hidden end button, `initialTime` only). Shared React GameScreen needs backward-compatible **optional controlled props** in these same components; their default IDs and SSR-only `GamePage.astro` consumers stay intact until migration.
- `apps/web/src/lib/games/core/GameInitializer.ts` is a legacy DOM-ID initializer with no production consumers beyond its barrel re-export and its own tests. Removing it when all game screens have moved is appropriate; keep `BaseRenderer` and `RendererFactory`, which are live.

## Design decisions

### 1. Ownership and package structure

- Create `packages/app-core` (TypeScript/TSX source exports, React peer dependency, dependencies only on `@cetus/shared` and `@cetus/games` **when actually imported**; no `@cetus/api-client` dependency without a consumer; no Pixi, Astro, Better Auth, DB, web alias, `window`, `document`, `HTMLElement` or browser UI runtime). React hook implementations can use `useEffect`, `useReducer` and `useSyncExternalStore` only when a concrete need arises; do not introduce Zustand, Redux, SWR, React Query or a general service container.
- Create **one small route-specific island per game**, e.g. `apps/web/src/components/islands/games/SnakeScreen.tsx`, with static imports for game chrome and panels so Astro can SSR stable IDs; import the Pixi/DOM initializer with `import()` **inside its mount effect** to avoid SSR browser side effects. `GameScreen` is a **shared React component**, not one global island that switches on a string game ID. Each route passes only serializable props to its own island (`client:load`); no 23-entry loader registry or eager import of renderers. `@cetus/ui` remains presentational and imports no game engine or app-core state.
- Keep `apps/web/src/lib/games/<game>` as web-only Pixi / DOM / keyboard/pointer renderer adapters. They take an owned host element (`HTMLElement`) and callbacks, never look up their mount container by a global hard-coded ID. Preserve existing renderer timing and game physics. Any rules accidentally embedded in a page controller move to `@cetus/games` with a unit test.
- Define the **smallest necessary interface** between app-core and web **together with the Snake consumer**: a session adapter with start, optional pause/resume/reset/end, subscribe-to-snapshot/results and dispose. Build the BaseGame adapter in the Snake stage; add the three handle adapters only when migrating Circuit Hacker, Satellite Sync and Ice Slide. Do not write unused generic capabilities or rewrite either engine style.
- **Cached projected snapshots are mandatory:** `BaseGame.getState()` creates a fresh object on every call, and a raw `useSyncExternalStore` `getSnapshot()` over it can loop indefinitely. An adapter maintains one immutable cached projection (status, score, time and only that game's visible HUD fields, e.g. Snake length). Replace it and notify subscribers only when projected values actually change. Test repeated `getSnapshot` identity and state-change bursts with no visible change.
- No game-id-to-`import()` loader registry: the **existing 23 Astro route files** are the registration and lazy-loading boundaries. One route island statically composes the appropriate shared React chrome, then dynamically imports only its own renderer/initializer from its effect. No plugin registry, codegen or 23-way switch.

### 2. Hook behavior and API contracts

- `useGameSession(session)` tracks started/paused/finished, score, remaining time and final stats from a stable adapter. Subscribe once per session; unsubscribe on change/unmount; update React only on meaningful UI state changes, **not every Pixi frame**. Return straightforward actions and session snapshot; handle unavailable capabilities by hiding controls, not by adding fake methods. Reset/Play Again semantics are game-specific and must not accidentally auto-start.
- A BaseGame end invokes `onEnd` for immediate local completion, then emits saved achievements/challenge updates once the injected score call resolves. Distinguish the **structured** end payload from the timer-forwarded bare `end`; preserve the existing stale-run guard. **Notification ownership is explicit and exclusive:** standard **React-controlled BaseGame screens** use exactly **one web GameScreen/BaseGame notification forwarder**, removing the former per-game `game.on('end')` toast bridge as each migrates. The **four hosted field plates** preserve their existing BaseGame initializer toast bridge and **must not register that new forwarder** unless the old bridge is removed. The three handle-based games keep `saveGameScore` notification forwarding; GameScreen must **never** forward their rewards. This avoids unnecessary controller churn while enforcing exactly one toast owner **per actual screen**, regardless of session kind. The session adapter exposes result data for display, not as a second notification source. Test exactly one toast per successful save for both kinds, including stale responses. Never resubmit from a hook.
- **Only `useGameSession` is needed in app-core for this ticket.** Tetris, 2048 and Bejeweled currently call `getLeaderboard` and `getChallenges` *inside imperative controllers* and will continue to do so once those controllers are hosted; no consumer of `useLeaderboard` / `useChallenges` is created. **Defer all five unused data hooks** (`useLeaderboard`, `useChallenges`, `useProfile`, `useAchievements`, `useLoginRewards`) until a React screen actually needs them. Keep the existing typed API client, account/session data, app-wide achievement notifications and dashboard login rewards unchanged. No new endpoints, DTOs or cache layer.
- **Keep explicit parameter injection, without a provider/factory:** `useGameSession(session)` receives the session adapter; the web renderer adapter continues injecting `BaseGameConfig.submitScore`. Existing hosted field-plate controllers can instantiate `createApiClient()` just as they do today; do not route those calls through new hooks. Preserve guest/error handling and existing stale-save guards.
- **Runtime portability is not the test environment.** Use the already-installed React 19-compatible `@testing-library/react` / `renderHook` under the existing **jsdom Vitest** pattern for hook behavior; do not introduce deprecated `react-test-renderer` (React 19) or a separate renderer. Test the pure session adapter/event normalization in Node (`// @vitest-environment node` for focused files). Extend the root Vitest project list and consolidated coverage for app-core; enforce **no DOM in production app-core source** through package-boundary lint, an app-core `no-restricted-globals` rule for DOM globals, and a no-DOM TypeScript lib where possible. Test mocks, jsdom and testing-library dependencies are dev/test-only; no browser globals in the exported runtime.

### 3. Web screen composition and rendering

- `AppLayout.astro` continues SSR, metadata and session extraction; AppNotifications remains the sole owner of the global toast display functions. Each Astro route uses its **own named React island** (`<SnakeScreen client:load />`, etc.), which composes shared `GameScreen` chrome where appropriate. The route passes only serializable props, preserves the public URL and contains no inline game initializer script. Static chrome and panels render on the server; renderer/Pixi initialization remains in a client mount effect.
- The common chrome reuses existing `@cetus/ui` GameTitle, GameStats, GameControls, GameOverlay, Badge/Card rather than copying them. **Add optional controlled props**: overlay `open`, `score`, `onButtonClick`; controls `running`, `paused`, `onStart`, `onPause`, `onEnd`, `onReset` as needed; stats `score`, `time`. Omission preserves current markup, hidden/default values and SSR compatibility for unmigrated `GamePage.astro` routes. Keep exact default IDs (`start-btn`, `end-btn`, `game-over-overlay`, `score`, `time-remaining`, `pause-btn`, `play-again-btn`), semantics, keyboard/touch and styles. React owns these elements only on migrated standard/handle pages; remove old imperative HUD/overlay/button writes at that point. **No React reconciliation over a DOM subtree owned by an imperative controller.**
- The four **field plates are hosted, not React-rewritten**: move each existing inline page script essentially mechanically into `apps/web/src/lib/games/<game>/controller.ts`, exposing `mount(host: HTMLElement, signal: AbortSignal)` (plus a cleanup return for non-event resources). Each plate's route-specific React island renders the unchanged plate markup inside a **stable, non-reconciling host subtree**: the controller exclusively owns *all descendant DOM*, including panel templates, HUD, dialogs, keyboard and CSS class/visibility mutations. The React host owns only mount/cleanup and optional session observation, not the plate's internal HUD/menus. Avoid re-rendering/reconciling the host descendants while the controller runs (separate memoized/static host from changing hook state; handle state outside the host). Scope `querySelector`/`setText` to that host and preserve the current `AbortController` listener cleanup. Keep exact current field-plate UX and `createApiClient()` calls. Converting their panels to React can be a later consumer-driven ticket, **not part of this PR**.
- Renderers/controllers stay imperative behind an owned host `ref`. Mount once per island, with idempotent cleanup of rAF/timers, global listeners, Pixi resources, pending callbacks and only the debug handle owned by that instance. **Full-page Astro navigation unmount/remount is not a production feature here** (no ClientRouter/View Transitions). Validate cleanup and late-save suppression in focused RTL `unmount()` tests per session kind rather than adding Playwright remount/route-transition harnesses. Code should still tolerate StrictMode effect cleanup; no extra browser navigation framework.
- Preserve `window.<game>Game` names and useful return shapes for debugging; expose from the **web adapter**, not app-core. Keep `window.showAchievementAward` / `window.showChallengeComplete` exclusively in AppNotifications. No extra global event bus.
- For handle-based games, pass the existing host `container` and callbacks into `initializeCircuitHackerGame`, `initializeSatelliteSync` and Ice Slide init. Replace handle initializer `setText`/`showOverlay`/`resetButtons` DOM ownership with React state/controlled `@cetus/ui` props for those three screens, **without adding a second toast forwarder**. Preserve Ice Slide Campaign/Daily/Expedition, Undo/route choices/context and `saveGameScore` notifications. Handle-session results are display-only. No generic game-rules rewrite.
- Keep existing styles and tokens. Import field-plate CSS where it is actually used and add a precise Tailwind `@source` only if the new web files fall outside the already-scanned web tree. Do not create new art or sound assets.

### 4. Migration inventory and boundaries

**One pilot:** Snake.

**Fifteen standard GamePage games:** Memory Matrix, Mine Grid, Pattern Pulse, Potion Sorter, Chromatic Tide, Sudoku, Quick Math, Word Scramble, Reflex, Evader, Path Navigator, Signal Switch, Gravity Flip, Asteroid Drift, Rhythm Reactor.

**Three handle-based games:** Circuit Hacker, Satellite Sync, Ice Slide.

**Four bespoke field plates:** Tetris, 2048, Bejeweled, Bubble Shooter.

That is 1 + 15 + 3 + 4 = **23**. For each, track current route, initializer, mount node, controls, keyboard/pointer listeners, score submitter, rewards, last-run overlay, debug handle and cleanup ownership in the PR checklist; do not build a permanent manifest or migration framework.

## Tradeoffs and explicit exclusions

- Prefer a shared **lifecycle** and a few real reused UI elements, not 23 wholly identical layouts. Existing field-plate style is intentional.
- Keep the current typed API and score-saving ownership. The hooks are UI state synchronization, not another persistence layer.
- No Expo app/native component work (HPA-179/HPA-182/HPA-425), Skia or new game loop abstraction (HPA-533), major game mechanic rebalance, database schema change, external state/cache library, SFX or image generation.
- **One PR for HPA-393** with staged commits, not two PRs or a new ticket. Require explicit human review of the Snake pilot, each standard-game batch, the handle batch and **each field-plate controller extraction** before continuing. Record acknowledgments in the PR; CI alone is not review. Re-check/rebase `main` between large batches. Avoid backward-compatibility shims for unpublished consumers.

## Acceptance and verification

1. `@cetus/app-core` typechecks with **no browser globals in runtime sources**. Build the first adapter and `useGameSession` together with Snake; test hook behavior using existing React Testing Library + jsdom, pure adapter logic in Node. Test stable cached `getSnapshot()` identity and no re-render on unchanged projected state, duplicate-listener prevention, start/pause/end/reset, end-event payload discrimination, guest/error/stale-award behavior. Add the three handle adapters/tests **only when they have real consumers**. Package ESLint/TypeScript restrictions catch DOM/Astro/Pixi access in production app-core.
2. All **23** routes are thin Astro shells mounting **named per-game React islands** with shared GameScreen presentation or a hosted field-plate controller. **Delete `GamePage.astro` as soon as its 19 actual consumers migrate** (not tied to the four field plates). Delete obsolete root inline scripts, preserve route URLs, and keep every `window.<game>Game` name **and original useful handle shape**.
3. Snake, every other standard page, all three handle-based games and all four field plates play, pause/restart, conclude, save scores and surface achievements/challenge completion with the same timing and errors as before. Ice Slide run modes, Tetris/2048/Bejeweled/Bubble Shooter custom panels and guest behavior remain intact.
4. **Freeze current E2E selectors and debug-handle APIs.** Migration commits may add tests but must not rename or weaken existing IDs/selectors (`#start-btn`, `#end-btn`, `#game-over-overlay`, `#score`, `#time-remaining`, `#pause-btn`, `#play-again-btn`) or the debug-handle methods already asserted in `play-coverage.spec.ts`. Any necessary existing-spec edit is explicitly flagged and reviewed at the human checkpoint. Existing keyboard/touch, modal focus/Escape, mobile+desktop layout, notifications and normal full-page navigation remain covered by blocking Playwright tests; **cleanup, StrictMode effects and late-save after unmount are covered by RTL**, not new Playwright remount scenarios. Screenshots stay manual comparison artifacts only.
5. Run root format/lint, `turbo run typecheck`, web Astro check, consolidated unit/coverage (>=90% existing gates), build, and full Playwright (including all-games navigation + authenticated score submissions). When all live routes have migrated, **delete unused web `GameInitializer.ts`, its tests and barrel exports** after a final importer check; retain live `BaseRenderer`/`RendererFactory`, and update `CLAUDE.md` guidance and affected tests. Document pre-existing flakes separately instead of broadening scope.

## Review decisions (2026-10-27, PR #99)

- Round-1 scope initially retained `useLeaderboard` and `useChallenges` alongside `useGameSession`; **round 2 supersedes that decision** after choosing hosted field plates. Only `useGameSession` is built now; all five data hooks are deferred.
- Accepted plain parameter-injected API client rather than a React provider/hook factory.
- Accepted React Testing Library + jsdom for hook tests, pure adapter tests in Node; **portable runtime** is the no-DOM invariant, not a Node-only React test renderer.
- Accepted non-blocking local visual comparisons and existing Playwright gameplay assertions as blocking gates.
- Accepted staged mandatory human reviews **within the same PR**. Declined the proposed multi-PR alternative, following the one-ticket/one-PR project rule.

## Review decisions (2026-10-27, PR #99, round 2)

- All nine round-two findings accepted with two implementation clarifications: hosted field plates use a **single DOM owner** and stable non-reconciling host; notification owners are mutually exclusive **per screen** (new BaseGame forwarder on migrated standard React screens, existing initializer forwarder on hosted BaseGame plates, `saveGameScore` forwarder on handle games).
- Removed unused data hooks and the 23-game loader registry; only the Snake-driven session contract/hook is built upfront; handle adapters follow first consumer.
- Extend existing UI components with **optional** controlled props while keeping SSR defaults and exact IDs; cache projected BaseGame snapshots for `useSyncExternalStore`.
- Existing E2E selector + debug-handle shapes are frozen. DOM controller cleanup is RTL-tested, not Playwright view-transition tested, because the app uses full-page navigation.
- Delete unused `GameInitializer` and update `CLAUDE.md` **at implementation cleanup**, not while the source still exists.
